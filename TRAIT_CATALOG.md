# Каталог признаков и проверка весов

Стандартная анкета состоит из **23 бинарных вопросов**: 0 означает условно фемининный вариант, 1 — условно маскулинный. Это философская модель, а не клиническая методика. Реальные признаки и поведение могут не укладываться в две категории. Формулировки вопросов и вариантов ответов находятся в `traits.mjs`.

Это математическое ограничение, а не доказательство содержательной правильности выбранных весов.

Поведенческие варианты — условные культурные коды. Не следует использовать их для утверждений о реальном поле, гендере или ориентации человека. Шесть поведенческих ответов могут коррелировать друг с другом. Категории предназначены для организации анкеты, **их доли не задаются отдельно**.

## Одна формула для всех признаков

Только включённые вопросы участвуют в вычислении:

\[
I(x)=\frac{\sum_i w_i(2x_i-1)}{\sum_i w_i}.
\]

Категории не получают фиксированных процентных квот. Все веса относятся к одному и тому же знаменателю; сумма стандартных весов составляет **21.05**. Поведенческая часть составляет `6 / 21.05 ≈ 28.5%` общей суммы **при всех включённых признаках**; это математическое следствие текущих весов, а не отдельное правило модели.

## Аксиома \(I\ne0\) и пользовательские веса

Для полного набора бинарных ответов точный ноль возможен тогда и только тогда, когда найдётся подмножество активных весов, сумма которого равна половине общей суммы. Для стандартных весов в единицах по 0.05 получаем целые числа с **нечётной суммой 421**. Поэтому ни одно подмножество не может составить точно половину суммы и \(I(x)\ne0\) для всех \(2^{23}\) наборов ответов.

В пользовательской анкете можно изменять вопросы, включённость и веса, **не получая автоматических поправок**. При каждом изменении приложение проверяет возможность нуля с помощью точной десятичной арифметики и поиска суммы подмножества. Для вычислительно сложных наборов высокой точности результат проверки может быть **«не удалось установить»**, а не ошибочно объявляться допустимым.

- **Нет нуля:** предупреждение не показывается.
- **Возможен ноль:** в конструкторе появляется предупреждение; веса не изменяются; при ненулевых текущих профилях вычисление продолжается.
- **Текущий профиль имеет \(I=0\):** положение на треугольнике не выдаётся, потому что нарушена аксиома.
- **Проверка не завершена:** конструктор показывает предупреждение о невозможности гарантировать выполнение аксиомы.

Пример: веса `[1,1]` позволяют нулевую сумму, а `[1,2,4]` — нет. Это ограничение относится к **всем возможным наборам ответов**, а не только к уже заполненным профилям. При отключении признаков набор активных весов меняется, и проверка выполняется заново.

## Совместимость

Формат проекта `representation-triangle-ru-v3` и ключ `localStorage` не изменились. Из ранее сохранённой **встроенной** анкеты с 16 признаками выполняется явная миграция до 23 с сохранением прежних ответов, партнёров и их весов. Начальные значения новых ответов остаются задокументированными в `questionnaires.mjs`. Пользовательские копии и собственные анкеты не расширяются автоматически.

У старых проектов могло существовать поле `behaviorContribution` — параметр групповой схемы 80/20. Для пользовательских анкет оно сохраняется в JSON для совместимости, но **больше не влияет на расчёты**, поскольку применяется единая формула. Для встроенной анкеты при миграции этот устаревший параметр удаляется из активной конфигурации.

В статье Word математические предпосылки и треугольник изложены отдельно; актуальные веса, миграция и проверка допустимости документированы здесь.
